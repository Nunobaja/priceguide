# Guía interna para preparar propuestas comerciales

## 1. Propósito

Esta guía se usa después de una conversación de venta para enviar una oferta pagada, clara y por escrito a un negocio local de servicios para el hogar en México.

Precios Locales es una página individual sencilla de rangos de precios orientativos para un negocio local de servicios para el hogar en México. Ayuda a sus clientes a entender rangos aproximados de servicios antes de comunicarse directamente con el negocio.

La propuesta se prepara, completa y envía manualmente. No es una página de cobro, un sistema de pagos, un CRM, un motor de cotizaciones, un sistema de análisis, un flujo para captar datos de prospectos ni un generador de contratos. Tampoco convierte la aplicación en un directorio, mercado de proveedores, sistema de reservaciones o plataforma de reseñas.

La página presenta una **estimación**, un **rango aproximado** o un **precio aproximado**. No promete el importe definitivo: **el precio final depende de los detalles del servicio** y **el negocio confirma el precio final directamente con el cliente**.

Copia y completa la [plantilla reutilizable de propuesta](templates/client-proposal.md). Todo dato que todavía no haya sido acordado debe marcarse como **Pendiente**.

## 2. Cuándo usarla

Usa esta guía:

- Después de que un prospecto muestre interés.
- Después de presentar una demostración.
- Después de elegir el paquete Básico, Pro o Local Completo.
- Antes de iniciar la incorporación.
- Antes de solicitar o recopilar datos del negocio.
- Antes de publicar una página o actualizar una página existente.

No envíes la propuesta si todavía no puedes explicar con claridad el paquete, el precio, el tiempo de entrega, lo incluido, lo no incluido y el siguiente paso.

## 3. Marcadores obligatorios

Conserva los nombres exactamente como aparecen aquí. Sustituye cada marcador por información confirmada o escribe **Pendiente**.

| Marcador | Qué debe contener |
| --- | --- |
| `{clientName}` | Nombre de la persona que recibe y aprueba la propuesta. |
| `{businessName}` | Nombre público del negocio. |
| `{businessCategory}` | Categoría principal de servicios para el hogar. |
| `{businessCity}` | Ciudad principal del negocio. |
| `{businessState}` | Estado de México donde opera el negocio. |
| `{packageName}` | Paquete elegido: Básico, Pro o Local Completo. |
| `{setupPrice}` | Precio acordado por la preparación y entrega inicial. |

| `{deliveryTime}` | Tiempo de entrega acordado y condición para iniciarlo. |
| `{includedItems}` | Lista concreta de entregables incluidos. |
| `{notIncludedItems}` | Lista concreta de límites y conceptos fuera del alcance. |

## 4. Estructura de la propuesta

### Saludo

Dirígete a `{clientName}` y menciona a `{businessName}`. Mantén un tono directo, profesional y natural.

### Problema observado

Resume lo escuchado en la conversación sin inventar necesidades. Ejemplo: los clientes preguntan precios básicos por mensaje antes de explicar el servicio que necesitan.

### Solución propuesta

Presenta una sola página individual para `{businessName}` con rangos aproximados, preguntas de servicio y una salida directa a WhatsApp o llamada. No la describas como un sitio de múltiples proveedores ni como una herramienta que entrega un importe definitivo.

### Qué se entregará

Enumera resultados concretos: página individual, servicios, rangos aproximados, preguntas, zonas, datos de contacto y materiales adicionales únicamente cuando formen parte del paquete.

### Qué está incluido

Copia `{includedItems}` y aclara el límite de servicios, revisiones, enlaces, materiales y mantenimiento.

### Qué no está incluido

Copia `{notIncludedItems}` y conserva los límites comerciales de esta guía. No dejes que una conversación informal amplíe el alcance.

### Tiempo

Indica `{deliveryTime}` y desde qué momento empieza a contarse: normalmente, después de recibir la información completa y confirmada.

### Precio

Separa `{setupPrice}`, `{monthlyPrice}` y `{updateFee}`. No presentes una cuota opcional como obligación ni incluyas instrucciones de pago inventadas.

### Responsabilidades del cliente

Explica qué datos debe proporcionar y confirmar `{clientName}` antes de publicar.

### Límites seguros

Aclara que los importes de los servicios son orientativos, que los resultados comerciales no se garantizan y que el contacto, la confirmación del servicio y el precio definitivo ocurren directamente con el negocio.

### Siguiente paso

Usa `{nextStep}` para pedir una respuesta concreta, por ejemplo aprobar el alcance y autorizar el inicio de la incorporación manual.

## 6. Claridad de alcance

Toda propuesta debe dejar por escrito:

- Se prepara **una página individual por negocio**.
- La página muestra rangos aproximados de servicios, no importes definitivos.
- Se incluyen preguntas de servicio para orientar la conversación con el negocio.
- El siguiente contacto ocurre por WhatsApp o llamada, según los datos públicos confirmados.
- Los enlaces por fuente sólo se entregan si `{sourceLinksIncluded}` los contempla.
- El código QR y los materiales imprimibles sólo se entregan si `{qrIncluded}` los contempla.
- La preparación, revisión y entrega son manuales.
- Las actualizaciones sólo se realizan cuando `{maintenanceIncluded}` las incluye o cuando se acuerda `{updateFee}` por separado.

Si un elemento no está confirmado, escribe **Pendiente**. Si no forma parte del paquete, escribe **No incluido**.

## 7. Responsabilidades del cliente

Antes de publicar, `{clientName}` debe:

- Proporcionar el nombre público de `{businessName}`.
- Confirmar `{servicesIncluded}`.
- Confirmar `{zonesServed}`.
- Confirmar el teléfono público.
- Confirmar si ese teléfono recibe mensajes de WhatsApp.
- Confirmar los rangos aproximados de cada servicio.
- Confirmar qué factores pueden cambiar el precio.
- Confirmar materiales, trabajos, traslados u otros conceptos no incluidos.
- Revisar y aprobar el enlace final antes de compartirlo.

El equipo no debe inventar datos, completar respuestas dudosas ni publicar un rango sin aprobación.

## 8. Qué no está incluido

La propuesta debe indicar de manera expresa:

- No se garantiza una posición en Google.
- No se garantiza una cantidad de contactos interesados.
- No se garantizan ventas ni resultados comerciales.
- No se promete un importe definitivo antes de conocer los detalles del servicio.
- No se administran anuncios pagados, salvo que exista un acuerdo separado y explícito.
- No incluye un CRM.
- No incluye un panel de análisis.
- No incluye seguimiento digital de visitantes.
- No incluye reservaciones.
- No recibe ni procesa cobros.
- No incluye reseñas ni calificaciones.
- No publica al negocio dentro de un mercado o listado para comparar proveedores.
- No funciona como motor automático de cotizaciones.

## 9. Lenguaje seguro sobre precios

### Expresiones permitidas

- “Rango aproximado”.
- “Estimación”.
- “Precio aproximado”.
- “El precio final depende de los detalles del servicio”.
- “El negocio confirma el precio final directamente con el cliente”.
- “Los importes pueden cambiar por materiales, alcance, ubicación, urgencia o condiciones del trabajo”.

### Expresiones que no deben usarse

No describas la página como una cotización asegurada, no prometas un precio definitivo invariable, no presentes los importes como exactos y no garantices resultados. Si una frase elimina la necesidad de que el negocio revise los detalles, reemplázala por “rango aproximado” o “estimación”.

## 10. Mensajes de aceptación y siguiente paso

### Aceptación por WhatsApp

```text
Hola, {clientName}. Te comparto la propuesta para la página individual de {businessName}.

Paquete: {packageName}
Preparación inicial: {setupPrice}
Mantenimiento mensual: {monthlyPrice}
Actualización separada: {updateFee}
Tiempo de entrega: {deliveryTime}

La página mostrará rangos aproximados y preguntas de servicio antes de que la persona se comunique directamente con el negocio. El precio final depende de los detalles del servicio y {businessName} lo confirma directamente con su cliente.

Si apruebas el alcance, responde: “Acepto la propuesta y deseo continuar con el siguiente paso: {nextStep}”.

Fecha: {proposalDate}
Preparó: {publisherName}
```

### Aceptación por correo

**Asunto:** Propuesta para la página individual de `{businessName}`

```text
Hola, {clientName}:

Gracias por la conversación. Adjunto la propuesta del paquete {packageName} para {businessName}, con el alcance, los límites, el precio y el tiempo de entrega acordados.

La página comunicará estimaciones y rangos aproximados de {servicesIncluded}. El precio final depende de los detalles del servicio y el negocio lo confirma directamente con el cliente.

Para aceptar, responde a este correo con: “Acepto la propuesta y deseo continuar con {nextStep}”. Si necesitas una corrección, indícame el punto específico antes de aprobar.

Fecha de propuesta: {proposalDate}
Preparó: {publisherName}
```

### Seguimiento si no hay respuesta

```text
Hola, {clientName}. Retomo la propuesta de {businessName} enviada el {proposalDate}. ¿Pudiste revisar el paquete {packageName}, el alcance y el precio? Si algo debe cambiar, dime qué punto. Si deseas continuar, el siguiente paso es: {nextStep}.
```

### Mensaje después de que el cliente dice que sí

```text
Gracias, {clientName}. Queda aceptada la propuesta del paquete {packageName} para {businessName}. Antes de iniciar, confirmaré contigo el alcance y solicitaré la información de incorporación. La entrega estimada es {deliveryTime} a partir de que recibamos todos los datos completos y confirmados.
```

### Solicitud de información de incorporación

```text
Hola, {clientName}. Para preparar la página individual de {businessName}, por favor completa la plantilla de incorporación con:

- Nombre público del negocio.
- Servicios que deben aparecer.
- Zonas atendidas.
- Teléfono público y confirmación de WhatsApp.
- Rangos aproximados.
- Factores que afectan el precio.
- Conceptos no incluidos.

Si todavía no conoces una respuesta, márcala como Pendiente. No publicaremos rangos ni datos sin tu confirmación.

Siguiente paso acordado: {nextStep}
Responsable: {publisherName}
```

## 11. Redacción sobre el pago

El pago se gestiona manualmente fuera de la aplicación. Este repositorio y la aplicación no procesan pagos, no deben incorporar una página de cobro y no deben registrar métodos de pago.

En la propuesta basta con indicar:

```text
La forma y el momento del pago se confirman directamente con {publisherName} fuera de la aplicación. Esta propuesta no procesa el pago.
```

Mantén las instrucciones genéricas y manuales. No agregues datos bancarios ni inventes métodos, cuentas, enlaces o condiciones que no hayan sido confirmados.
