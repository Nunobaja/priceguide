## 8. Normalización interna para Precios Locales

### Ruta pública

Todos los slugs deben estar en minúsculas, sin acentos, sin espacios y separados con guiones.

- **`citySlug`:** `[ciudad]`
- **`categorySlug`:** `[categoria]`
- **`businessSlug`:** `[nombre-del-negocio]`
- **Ruta esperada:** `/[citySlug]/[categorySlug]/[businessSlug]`
- [ ] La ruta no está duplicada en `businesses.js`.
- [ ] La ruta describe correctamente ciudad, categoría y negocio.

### Zonas y factores

La zona base usa `factor: 1.0`. Convierte un porcentaje de recargo a factor con `1 + porcentaje / 100`; por ejemplo, 15% se registra como `1.15`. Si el negocio dio montos fijos por traslado, ajusta los rangos o documenta la decisión antes de convertirlos a factores.

| Etiqueta pública de zona | Recargo informado | `factor` acordado | Validado |
|---|---:|---:|---|
| [Zona base] | 0% | 1.0 | [ ] |
| [Zona] | [% o $] | [1.00] | [ ] |
| [Zona] | [% o $] | [1.00] | [ ] |
| [Zona] | [% o $] | [1.00] | [ ] |

### Servicios, preguntas y opciones

- Cada `service.id` debe ser único dentro del negocio.
- Cada `question.id` debe ser único dentro de su servicio.
- `base` contiene `[mínimo, máximo]`, ambos como números sin `$` ni separadores.
- Una respuesta neutral debe usar `factor: 1.0`.
- Usa `factor` para cambios proporcionales (por ejemplo, 25% más → `1.25`).
- Usa `add` para sumar una cantidad fija (por ejemplo, $300 más → `add: 300`).
- Si una opción combina ambos ajustes, puede incluir `factor` y `add`.
- No uses factores calculados sin comprobar los tres casos de prueba con el negocio.
